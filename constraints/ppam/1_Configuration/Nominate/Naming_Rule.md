# Naming Rule — 命名规范

本包全局命名规范。所有文件夹与文件名必须遵循。

## 基本规则

1. **严禁缩写**：要么全称，要么约定字母缩写（如 PPAM）
2. **首字母大写**：文件夹名首字母大写，不用全大写
3. **特殊强调用全大写**：仅特殊单个文件用全大写（如 INDEX.md、Request.md、Expand.md）
4. **词组用 `_` 连接**：连续关系词组用下划线（如 `Prompt_Optimization.md`、`Grill_Init.js`）
5. **非组合并列用 `-` 连接**：不同元素词并列、非组合关系用连字符
6. **全英文字符**：禁止乱七八糟的驼峰，禁止非英文字符
7. **数字前缀**：所有顶层大文件夹用数字前缀标注严格逻辑顺序，格式 `N_Xxx`，不允许乱标凑人头

## 示例

| 类型 | 示例 | 说明 |
|------|------|------|
| 顶层文件夹 | `1_Configuration` | 数字前缀 + 首字母大写 |
| 顶层文件夹 | `2_Request` | 数字前缀 + 首字母大写 |
| 词组文件 | `Prompt_Optimization.md` | 词组用 `_` 连接 |
| 词组文件 | `Grill_Init.js` | 词组用 `_` 连接 |
| 特殊强调文件 | `INDEX.md` | 全大写 |
| 特殊强调文件 | `Request.md` | 全大写 |
| 并列元素 | `User-Admin` | 非组合并列用 `-` |

## 数字编号原则

顶层文件夹按逻辑顺序编号，编号必须反映严格逻辑关系：

```
1_Configuration  →  系统内部配置（起点，独立基础设施）
2_Request        →  对 AI 的核心要求（规则源头）
3_Prompt         →  用户提示词优化规范（基于 Request 标准）
4_Expand         →  可拓展层（基于固定规则增强）
```

逻辑链：配置先行 → 规则定标准 → 标准优化输入 → 拓展增强行为。

## 例外

- `package.json` / `.gitignore` 等工具约定文件保持原名（工具硬性要求）
- `.trae/` 等工具约定路径保持原名（工具硬性要求）
- 第三方参考资料（`4_Expand/references/`）保持原命名，不动
