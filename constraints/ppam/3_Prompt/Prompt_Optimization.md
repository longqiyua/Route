# Prompt — 用户提示词优化规范

本文件是 AI 处理用户输入提示词时的优化规范。**AI 获得用户提示词后，必须先看本文件**，再决定是否让用户修改或 AI 自优化。优化标准：符合 `2_Request/` 中对 AI 的核心要求。

## 何时触发

AI 每次收到用户输入的提示词（需求、指令、问题）时，在执行前必须过本规范。

## 优化流程

### 1. 解析用户意图

从用户输入中提取：
- **意图类型**：需求 / 写码 / 修 bug / 加功能 / 其他
- **关键信息**：目标对象、约束条件、期望产出
- **缺失信息**：哪些是 `2_Request/` 要求但用户没提供的

### 2. 对照 Request 标准

按 `2_Request/Request.md` 的四阶段要求检查用户提示词：

| 意图类型 | 必须满足的标准 | 不满足时的动作 |
|---------|---------------|---------------|
| 需求 | 问题陈述清晰、用户故事可推导、验收标准隐含或明确 | AI 自优化补全 + 向用户确认 |
| 写码 | 对应待办项存在、兼容性影响可评估 | 无待办则回阶段一补需求 |
| 修 bug | 现象可复现、用户视角症状清晰 | 引导用户补复现步骤 |
| 加功能 | 三闸门状态可查 | 先查三闸门，不绿先回阶段三 |

### 3. 优化决策

**AI 自优化**（默认优先，不打扰用户）：
- 补全缺失但可推断的信息
- 规范化术语（对照 `.vibe/context.md`）
- 补充验收标准
- 标注约束与范围外

**让用户修改**（以下情况必须先问用户）：
- 意图歧义无法推断（比如"改一下那个"——改哪个？）
- 决策性问题（技术选型、方案选择）
- 兼容性破坏风险
- 范围明显超出当前阶段（比如三闸门没过就要加功能）

### 4. 优化后输出

AI 内部形成优化版提示词，含：
- 规范化意图
- 关联的待办/bug/需求编号
- 对照 request 标准的检查结果
- 待确认项（如有）

然后按 `request/` 规则进入对应阶段执行。

## 优化原则

1. **最小打扰**：能自优化就不问用户，只在决策性/歧义/破坏性时才打断
2. **标准对齐**：一切优化以 `request/` 要求为准，不擅自加码或放水
3. **术语一致**：用 `.vibe/context.md` 的术语，不用同义词替换
4. **保留原意**：优化是规范化，不是改变用户意图
5. **透明可追溯**：优化后的提示词与原始输入的对应关系可说明

## 反模式（禁止）

- 用户说"加个登录"就直接写码——必须先确认待办存在、补需求
- 用户报 bug 就直接猜原因——必须先过阶段三诊断循环
- 用户要加功能就加——必须先过三闸门
- 自优化时擅自扩大范围或加用户没要求的功能
- 用同义词替换用户术语（破坏语境一致性）

## 与其他文件的关系

- 上游：用户原始输入
- 标准：`2_Request/Request.md`（四阶段 + 全局约束）
- 语境：`.vibe/context.md`（术语表）
- 拓展：`4_Expand/`（用户自定义规则，可能影响优化方向）
