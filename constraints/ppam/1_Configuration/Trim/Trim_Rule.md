# Trim Rule — 整理规范

本文件定义 PPAM 包的自动整理规则。当读取本包的 AI 发现用户乱放文件、隐含配置散落、结构混乱时，按本规则自动整理，强制对齐 PPAM 分类标准。

## 触发条件

AI 在以下情况触发自动整理：
1. 每次对话开始扫描项目根时发现散落文件（不在任何顶层文件夹内）
2. 用户往错误位置放文件（如把规则文件放进 4_Expand 而非 2_Request）
3. 发现隐含配置文件散落在根目录或错误位置
4. 文件/文件夹命名不符合 `1_Configuration/Nominate/Naming_Rule.md`
5. 4_Expand 下内容与固定规则冲突且未经用户确认

## 整理优先级（最高优先级，不可覆盖）

PPAM 的分类标准是最高优先级。任何用户的乱搞、隐含配置文件、非标准放置，都按本规则整理。用户自定义内容只能在 `4_Expand/` 内，不得越界。

## 分类强制规则

| 文件类型 | 必须归属 | 理由 |
|---------|---------|------|
| 对 AI 的核心要求/规则 | `2_Request/` | 规则源头 |
| 用户提示词优化规范 | `3_Prompt/` | 优化层 |
| 用户自定义参考资料/规则/示例 | `4_Expand/` | 拓展层 |
| 脚本/CI/工具配置 | `1_Configuration/` | 内部配置 |
| 命名规范 | `1_Configuration/Nominate/` | 独立规则 |
| 整理规范 | `1_Configuration/Trim/` | 独立规则 |
| 工具约定文件（package.json/.gitignore） | 根目录 | 工具硬性要求 |

## 整理动作

### 1. 散落文件归位

发现根目录散落文件（非工具约定）：
- 识别文件性质（规则/配置/参考资料/文档）
- 移动到对应顶层文件夹
- 在原位置不留副本

### 2. 错误位置纠正

发现文件在错误文件夹：
- 移动到正确位置
- 更新所有引用该文件路径的地方
- 通知用户已纠正

### 3. 命名规范化

发现文件/文件夹命名不符合 Naming_Rule：
- 按规则重命名
- 更新所有引用
- 通知用户已重命名

### 4. 隐含配置处理

发现用户散落的隐含配置文件（如 `.env`、自定义 config）：
- 若属于 PPAM 配置范畴 → 移入 `1_Configuration/`
- 若属于用户项目配置 → 不动，但提醒用户该文件位置
- 若属于工具约定 → 不动

### 5. 4_Expand 冲突处理

4_Expand 内容与固定规则冲突时：
- 不自动修改固定规则
- 不自动删除 4_Expand 内容
- **主动提醒用户**说明冲突点与两方内容，让用户决定

## 整理后输出

每次自动整理后，AI 输出整理报告：
```
## Trim 整理报告 — <日期> #<对话编号>
- 发现：<问题列表>
- 动作：<移动/重命名/纠正列表>
- 结果：<整理后状态>
- 待用户确认：<如有冲突未决项>
```

整理报告追加到 `.vibe/changelog.md`（若已运行时初始化）或直接告知用户（若尚未进入运行时）。

## 禁止动作

- 不删除用户文件（只移动）
- 不修改 4_Expand 内用户自定义内容（冲突只提醒不自动改）
- 不修改工具约定文件（package.json/.gitignore 等）
- 不修改第三方参考资料（4_Expand 下 anthropic-skills/skills-main 等）
- 不在未通知用户情况下静默整理（必须输出整理报告）
