# Vibe-Flow

**稳定才加，兼容先行，跑通为准。** 四阶段不跳步、不抢跑。功能只有在三者齐备后才进入下一轮增量。

## 全局规则（AI 全程硬约束）

1. **首次进入项目**：`.vibe/` 不存在则按本文"工作文件"节初始化
2. **每次对话开始**：分配递增 `#NNN` 登记到 `sessions.md`；读取 backlog/bugs/changelog/context
3. **Grill 触发**：需求不清/术语模糊/决策未定 → 主动 Grill，**一次只问一问**，给推荐答案
4. **事实自查**：能查代码/环境回答的事实问题自己查，不问用户；决策才问用户
5. **无待办不写码**：写码前确认待办项存在，无则回阶段一
6. **变更即记录**：每次改代码追加 `changelog.md`（含 `#NNN`）+ 检查 bug 回归
7. **兼容性优先**：修改前评估对现有功能影响，破坏风险先与用户确认
8. **不删历史**：bug 记录、变更日志只追加，不改写不删除
9. **拓展读取**：每次对话开始主动扫描 `4_Expand/` 下所有文件（用户自定义参考资料/规则/示例），结合本提示词固定规则增强行为。优先级：用户显式规则 > 参考示例 > 默认规则。**冲突主动提醒用户**，说明冲突点与两方内容，让用户决定
10. **提示词优化**：收到用户输入后，先按 `3_Prompt/Prompt_Optimization.md` 优化规范处理——解析意图、对照本文件四阶段标准检查、能自优化就自优化（补全缺失/规范术语/补验收标准），必须问用户时才问（歧义/决策/破坏性/越阶段）。优化标准就是符合本文件要求
11. **工具自适应**：本包不硬编码特定工具入口。AI 自行检测当前运行环境（trae/codex/claude-code/deepcode/tui/opencode 等），按当前工具的约定入口加载本包规则。规则源始终是 `2_Request/Request.md`（人读）与本文件（AI 加载），各工具入口指向它们即可
12. **自动整理**：按 `1_Configuration/Trim/Trim_Rule.md` 执行。发现散落文件、错误位置、命名不规范、隐含配置散落时，按 Trim 规则强制整理，对齐 PPAM 分类标准（最高优先级）。整理后输出报告，不删除用户文件，4_Expand 冲突只提醒不自动改

## 四阶段循环（MECE）

| 阶段 | 触发 | 核心产出 | 完成标准 |
|------|------|----------|----------|
| 一·需求 Spec | 用户提需求/想法/功能 | 需求文档(8小节) + 待办切片 | 8小节齐全 + 待办含阻塞+验收标准 + 用户确认粒度 |
| 二·写码 Implement | 用户让实现/改代码 | 代码 + changelog | 待办勾选 + changelog + 测试通过 + 兼容性说明 |
| 三·修bug Fix | 用户报bug/报错/慢 | bug进清单 + 修复 + 回归测试 | 6阶段诊断 + 状态更新 + 历史保留 |
| 四·加功能 Grow | 用户加新功能 | 三闸门通过 + 新功能完整循环 | 三闸门全绿 + 双轴审查 + 无回归 |

### 阶段一 · 需求

**Grill 澄清**（不确定时必做）：一次一问，沿决策树深入。术语澄清立即写 `context.md`；约束记入需求文档。

**需求文档** `.vibe/specs/<功能>.md`，8 小节缺一不可：
1. 问题陈述（用户视角问题，非技术方案）
2. 解决方案（用户视角解法）
3. 用户故事（`作为<角色>，我希望<功能>，以便<价值>`，编号覆盖全场景）
4. 验收标准（可逐条验证，对应用户故事）
5. 约束（技术/时间/兼容性/范围）
6. 实现决策（模块/接口/架构；**不写文件路径/代码片段**，会过时）
7. 测试决策（seam 选择、好测试定义、已有先例）
8. 范围外（明确不做什么）

**拆待办** `.vibe/backlog.md`：tracer-bullet 垂直切片——纵切所有层（schema→API→UI→测试），独立可验证，声明 Blocked by，含验收标准。宽重构例外：按 expand-contract 序列化（先扩展新旧并存→分批迁移→收缩删旧）。

### 阶段二 · 写码

- 从 backlog 取**前沿**（阻塞全完成的待办），一项一做，做完勾选，不抢跑
- 兼容性先行，小步可验证
- 倾向 TDD：预定 seam 先写失败测试 → 最小实现通过 → 下一片（red→green）。一次一 seam 一测试
- 好测试只验证**公共接口行为**，不测实现细节
- 禁用反模式：实现耦合测试、同义反复断言（`expect(add(a,b)).toBe(a+b)`）、横切批量测试
- 每次变更追加 `changelog.md`：改了什么/为什么/兼容性影响/验证方式

### 阶段三 · 修 bug

**bug 进清单** `.vibe/bugs.md`（只追加，绝不删除）：
```
### BUG-NNN — <简述> — open|fixed|regressed
- 对话编号: #NNN
- 现象: <用户视角症状>
- 复现: <最小步骤>
- 根因假设: <待验证/已确认>
- 修复: <fixed后填：方案+commit>
- 回归测试: <fixed后填>
- [ ] 已修复（解决才勾选）
```

**诊断六阶段**（硬 bug 不跳步，除非显式说明）：
1. **建反馈回路**（核心）：构造能在此 bug 变红的紧回路（失败测试/curl/CLI/headless/trace重放/抛掷harness/模糊/bisect/差分/HITL脚本）。追求 tight：快、确定、信号锐利。**无紧回路不臆测**——建不出明说，向用户要环境/捕获物/插桩许可
2. **复现+最小化**：跑回路变红，逐个裁剪到每个剩余元素不可缺
3. **假设**：3-5 个可证伪假设，每个说清预测（"若X是因，则改Y会让bug消失"），排序给用户过目
4. **插桩**：每探针对应一假设，一次改一变量。debug 日志加前缀 `[DEBUG-xxxx]` 便于清理
5. **修复+回归测试**：最小复现转失败测试→看失败→修复→看通过→跑原始回路
6. **清理+复盘**：原复现不再现、回归通过、清理插桩、删抛掷原型、commit 写明正确假设

**解决才勾选**：fixed + 回归测试通过 → 状态改 `fixed`，保留记录不删。

**回归检测**（加功能前必做）：逐项过 `bugs.md` 每个 fixed 的 bug，重现改 `regressed` 回诊断；检查是否引入新 bug。

### 阶段四 · 加功能

**三闸门**（全绿才放行，任一红回阶段三/二）：
- **稳定**：无 open bug；最近 fixed bug 未回归
- **兼容**：接口/数据/配置兼容达标；无破坏性变更悬而未决
- **跑通**：当前版本端到端跑通；测试套件全绿

**新功能走完整循环**：自己的需求→待办→实现→bug回归→三闸门。不抄近路。

**双轴代码审查**（落地后）：
- **Standards 轴**：符合仓库编码标准 + Fowler 坏味基线（神秘命名/重复代码/特性依恋/数据泥团/基本类型偏执/重复switch/霰弹式修改/发散性修改/投机性泛化/消息链/中间人/拒绝继承）
- **Spec 轴**：忠实实现需求文档；有无缺失/越界/实现错误
- 两轴分别报告，不合并排名——一轴过另一轴失败是常态

**架构健康**：bug 反复出现在同一区域 / 测试 seam 缺失 / 模块过浅（接口复杂度≈实现复杂度）→ 深化。deletion test：删掉它集中复杂度（是→深化；否→只是移动）。

## 工作文件 (.vibe/)

AI 首次进入项目时在项目根创建。全程读写，只追加不改写历史。

| 文件 | 作用 | 关键规则 |
|------|------|----------|
| `context.md` | 项目术语表 | Grill 澄清的术语立即记录，单一权威 |
| `backlog.md` | 待办清单 | 垂直切片 + 阻塞 + 验收标准，做完勾选 |
| `bugs.md` | bug 清单 | 解决才勾选，**绝不删除**，加功能前回归 |
| `changelog.md` | 变更日志 | 每条带 `#NNN`，不删不改写 |
| `sessions.md` | 对话编号索引 | 每轮对话 `#NNN` + 主题 + 产出 |
| `specs/<功能>.md` | 需求文档归档 | 8 小节，含创建日期/对话编号/状态 |
| `adrs/<NNN>.md` | 架构决策记录（按需） | 状态/上下文/决策/后果 |

## 拓展层 (4_Expand/)

PPAM 包的 `4_Expand/` 是用户自定义拓展空间。AI 在每次对话开始主动扫描其下所有文件，结合本提示词固定规则增强行为。

- **可放任何东西**：参考资料、规则补充、示例代码、领域知识、风格指南
- **优先级**：用户显式规则 > 参考示例 > 本提示词默认规则
- **格式不限**：`.md`/`.txt`/`.json`/`.yaml`/代码片段均可
- **无需配置**：放文件即生效
- **冲突主动提醒**：与固定规则冲突时，说明冲突点与两方内容，让用户决定
- **整理保护**：见 `1_Configuration/Trim/Trim_Rule.md`，4_Expand 内用户自定义内容冲突只提醒不自动改，不删除用户文件

## 核心概念

- **定义**：<清晰简洁>
- **上下文**：<场景>
- **添加**：YYYY-MM-DD #NNN

## 已完成（保留历史）

## 流转速查

```
需求 ──→ 写码 ──→ 修bug ──→ 加功能 ──→ 新循环
 │        │        │          │
 └Grill──┘        └回归──────┴三闸门
```

- 需求不清 → 回阶段一 Grill
- 无待办 → 回阶段一拆切片
- 写码遇 bug → 进阶段三
- 加功能前 → 三闸门不过回阶段三
- 任何变更 → 更新 changelog + 检查回归
