# 双通道大输出采集资源基线

本项验证既有 Q1 流式采集，不新增生产功能，不替换发布二进制。
原始结果见 [JSON](bounded-capture-baseline-2026-10-11.json)。

在 `tool/route` 显式执行（Windows）：

```powershell
cargo test -p route-basic bounded_capture_resource_baseline -- --ignored --nocapture
```

实际 exit=0，1 项测试通过，用时 75.94 秒（不含构建）。测试包含小输出基线、
每通道 1 GiB 采集及独立生成预期摘要的 CPU 成本；单次大输出采集约 25.68 秒。
每种规模只有一个样本，不报告 p50/p95，不声称机器负载已归一化。

| 每通道主体输出 | 采集用时 ms | 采集测试进程峰值工作集 bytes | 输出子进程峰值工作集 bytes |
| --- | ---: | ---: | ---: |
| 16 MiB | 460.2126 | 8,089,600 | 7,016,448 |
| 1 GiB | 25,683.5737 | 7,606,272 | 7,421,952 |

大输出为 stdout / stderr 各 1 GiB，加少量测试框架前缀和不同尾部标记，总计超过
2 GiB。两路均完整排空、全内容 hash 匹配、不同尾部包含在摘要内，预览各 2048 bytes，
非零退出码 7 正确保留。生产采集函数未改变。

## 测量方法和限制

- 使用同一 `debug` Rust 测试二进制的独立采集进程和独立输出进程；不是实际发布
  `route.exe`。原始 JSON 记录被测二进制 SHA-256 与大小，不能用当前重新构建的
  二进制替代该测量身份。
- 外层通过持有的 Windows 子进程句柄，在采集进程退出后读取系统峰值工作集。
  输出进程在完成输出并 flush 后、退出前读取自身峰值；最后的少量测量序列化开销
  不在它的采样窗口内。工作集不等于堆分配量或纯采集缓冲大小。
- 采集进程的峰值包括测试框架、零输出前缀探测、实际 capture、预期摘要生成及
  进程退出。未隔离这些组成部分。每种规模用新进程，避免历史峰值污染。
- 小规模峰值比大规模高是单次观测差异，不能解读为输出越大内存越低。这里只观察到
  该夹具的内存未随 64 倍输出量线性增加，不建立通用 RSS 上限。
- 输出按固定 64 KiB 块生成，预期 digest 通过重复字节流生成，不分配 GiB 级 Vec。
  `stdout_bytes` / `stderr_bytes` 是由已知夹具内容、框架前缀及尾部长度推导的字节数，
  并由完整摘要匹配验证，不是新加的生产输出计数器。
- 生成输出不落盘。临时目录仅保存一份 43 bytes 的输出进程计量 JSON，测试结束
  自动清理；不包含源码、对话或原始输出，不操作项目历史。存储 I/O 总字节未测。
- 测试看门狗最多等待 180 秒，只针对本测试创建的采集进程；它不是生产 deadline、
  取消或进程树治理。未测试继承管道的后代、嵌套 Job Object、Host 超时或恢复。
- 没有重跑旧的全量 `Command::output()` 实现来制造 2 GiB 内存压力。因此本报告
  不是旧/新 RSS 对照，也不证明最初 418 MiB 的进程占用原因已经定位或解决。

## 可复用入口

测试源码为 [资源夹具](../../tool/route/crates/route-basic/src/command_output_resource_tests.rs)，
测试直接调用 [生产采集函数](../../tool/route/crates/route-basic/src/command_output.rs)。
三项资源测试均默认忽略：外层基线显式启动私有采集／输出夹具。
不要用不带筛选的 `--ignored` 启动所有私有夹具；它们需要外层传入测量参数。
默认回归保留既有 16 MiB 双管道功能测试，避免日常测试额外生成 GiB 输出。

T0 的大输出子项取得实测证据；T0 全部基线和 T1 完整进程执行器仍未完成。
