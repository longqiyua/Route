# 🔤 项目术语表

这是项目的普遍语言，记录了所有共享的术语定义和概念理解。

## 📖 使用说明

### 更新原则
1. **及时更新**：Grill会话中澄清的术语立即记录
2. **保持简洁**：只记录核心定义，不包括实现细节
3. **共同维护**：所有参与者都有责任更新术语表
4. **单一路径**：这是项目术语的唯一权威来源

### 格式规范
- 使用Markdown格式
- 按领域分类组织
- 包含示例和上下文
- 注明创建/更新时间

## 🏗️ 核心概念

### 项目结构
- **Grill系统**：基于无情提问的需求澄清和工作流管理系统
- **CONTEXT.md**：本项目文件，项目的普遍语言术语表
- **ADR**：架构决策记录，记录难以逆转的关键决策
- **HITL任务**：需要人类参与的任务（Human in the Loop）
- **AFK任务**：AI可独立完成的任务（Away From Keyboard）

### 开发流程
- **决策树**：结构化的问题解决方法，沿着分支深入探索
- **共同理解**：AI和用户之间完全对齐的需求理解
- **产出导向**：每个Grill会话都产生具体文档和任务

## 🔧 技术术语

### 文件夹结构
- **.grill/**：Grill系统工作空间
- **src/**：项目源代码
- **docs/**：项目文档
- **tasks/**：任务管理文件
- **config/**：配置文件
- **data/**：数据文件
- **temp/**：临时文件（Git忽略）

### AI协作
- **主动Grill**：AI检测到需求不清晰时自动启动的提问过程
- **结构化提问**：一次只问一个问题，按决策依赖顺序
- **术语维护**：持续更新本项目术语表以确保理解一致

## 📊 项目管理

### 任务状态
- **🔴 紧急**：需要立即处理，今天内完成
- **🟡 重要**：优先级高，3天内完成
- **🟢 正常**：标准优先级，1周内完成
- **⚪ 低优先级**：有空时处理，无紧急时间要求

### 工作流阶段
- **🎤 需求提出**：用户描述需求或想法
- **🔍 Grill澄清**：通过提问建立共同理解
- **📝 文档建立**：创建术语表和决策记录
- **🎯 任务创建**：从决策创建具体实施任务
- **🔧 实施开发**：AI或开发者完成任务
- **🧪 测试验证**：验证功能正确性
- **📊 完成交付**：更新状态和文档

## 🎨 设计原则

### 框架设计
- **简化优先**：保持结构简单，易于理解和维护
- **Grill中心**：以Grill为核心驱动所有工作流
- **AI友好**：设计明确的协作规则和标准格式
- **渐进采用**：支持从简单开始逐步添加功能

### 文档标准
- **一致性**：所有文档使用相同术语和格式
- **实用性**：文档服务于实际开发需求
- **可维护性**：易于更新和扩展
- **可发现性**：重要信息容易找到

## 🔄 工作流集成

### Grill驱动开发
1. **需求入口**：所有需求都通过Grill澄清
2. **决策记录**：所有关键决策都记录为ADR
3. **术语同步**：所有术语都记录在CONTEXT.md
4. **任务跟踪**：所有实施都关联到具体任务

### CI/CD集成
- **结构验证**：验证项目结构符合规范
- **Grill验证**：验证Grill产出完整性和一致性
- **文档生成**：自动生成和更新文档
- **任务同步**：同步任务状态到项目管理工具

## 📝 术语添加指南

### 何时添加新术语
1. Grill会话中澄清的任何新概念
2. 设计讨论中定义的技术术语
3. 项目中引入的新技术或模式
4. 团队内部使用的特定术语

### 如何添加术语
```markdown
### [领域]术语
- **定义**：清晰简洁的定义
- **上下文**：使用的具体场景和背景
- **示例**：使用示例或代码片段
- **相关术语**：关联的其他术语
- **添加时间**：YYYY-MM-DD
- **添加人**：添加者姓名或AI
```

### 术语维护
- **定期回顾**：每月回顾和更新术语表
- **冲突解决**：发现术语冲突时启动Grill澄清
- **废弃标记**：不再使用的术语标记为废弃
- **版本跟踪**：重要术语变更记录版本信息
