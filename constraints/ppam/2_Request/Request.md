# Request — 对 AI 的核心要求

本文件夹是给人读的规则说明，告诉你这个提示词增强包**要求 AI 做什么**。

AI 实际加载的提示词本体在 `.trae/skills/vibe-flow/SKILL.md`（隐藏路径，TRAE 约定）。两边内容一致，区别只是：本文件给人看，那个文件给 AI 加载。

## 一句话

**稳定才加，兼容先行，跑通为准。** 四阶段不跳步、不抢跑，三者齐备才进下一轮。

## 四阶段循环

| 阶段 | 什么时候进 | AI 要产出什么 | 做完的标准 |
|------|-----------|--------------|-----------|
| 一·需求 | 用户提需求/想法 | 规范化需求文档 + 待办清单 | 8 小节齐全 + 待办含阻塞与验收标准 + 用户确认粒度 |
| 二·写码 | 用户让实现/改码 | 代码 + 变更日志 | 待办勾选 + 变更日志 + 测试通过 + 兼容性说明 |
| 三·修 bug | 用户报 bug/报错/慢 | bug 进清单 + 修复 + 回归测试 | 六阶段诊断 + 状态更新 + 历史保留 |
| 四·加功能 | 用户加新功能 | 三闸门通过 + 新功能完整循环 | 三闸门全绿 + 双轴审查 + 无回归 |

## 阶段一 · 需求

需求不清就主动 Grill（一次只问一个问题，沿决策树深入，给推荐答案）。能查代码回答的事实问题自己查，决策才问用户。

需求文档必须含 8 小节：问题陈述、解决方案、用户故事、验收标准、约束、实现决策、测试决策、范围外。不写具体文件路径/代码片段（会过时）。

待办清单拆成垂直切片（纵切所有层，独立可验证，声明阻塞关系，含验收标准）。

## 阶段二 · 写码

从待办清单取前沿（阻塞全完成的），一项一做，做完勾选，不抢跑。兼容性先行，小步可验证。倾向 TDD（先失败测试→最小实现→下一片）。每次变更追加变更日志：改了什么/为什么/兼容性影响/验证方式。

## 阶段三 · 修 bug

bug 进清单，只追加绝不删除。硬 bug 按六阶段诊断（不跳步）：建反馈回路→复现最小化→假设→插桩→修复加回归测试→清理复盘。解决才勾选，历史保留。加功能前回归所有已修 bug。

## 阶段四 · 加功能

三闸门全绿才放行：稳定（无 open bug、最近 fixed 未回归）、兼容（接口/数据/配置达标）、跑通（端到端可跑、测试全绿）。任一红回阶段三。新功能走完整循环。落地后做双轴代码审查（Standards 轴 + Spec 轴，分别报告不合并）。

## AI 全程硬约束

1. 首次进项目：`.vibe/` 不存在则按规则初始化工作文件
2. 每次对话开始：分配递增对话编号登记到 sessions；读取待办/bug/变更日志/术语表
3. Grill 触发：需求不清/术语模糊/决策未定 → 主动 Grill，一次一问，给推荐答案
4. 事实自查：能查代码/环境回答的自己查，不问用户；决策才问
5. 无待办不写码：写码前确认待办存在，无则回阶段一
6. 变更即记录：每次改代码追加变更日志（含对话编号）+ 检查 bug 回归
7. 兼容性优先：修改前评估对现有功能影响，破坏风险先与用户确认
8. 不删历史：bug 记录、变更日志只追加，不改写不删除
9. 拓展读取：每次对话开始扫描 `4_Expand/` 下所有文件，结合固定规则增强行为。用户显式规则 > 参考示例 > 默认规则。**冲突主动提醒用户**

## AI 运行时维护的工作文件

AI 在目标项目根创建 `.vibe/`，全程读写，只追加不改写历史：

| 文件 | 作用 | 规则 |
|------|------|------|
| `.vibe/context.md` | 项目术语表 | Grill 澄清的术语立即记录，单一权威 |
| `.vibe/backlog.md` | 待办清单 | 垂直切片 + 阻塞 + 验收标准，做完勾选 |
| `.vibe/bugs.md` | bug 清单 | 解决才勾选，绝不删除，加功能前回归 |
| `.vibe/changelog.md` | 变更日志 | 每条带对话编号，不删不改写 |
| `.vibe/sessions.md` | 对话编号索引 | 每轮对话编号 + 主题 + 产出 |
| `.vibe/specs/<功能>.md` | 需求文档归档 | 8 小节，含创建日期/对话编号/状态 |
| `.vibe/adrs/<编号>.md` | 架构决策记录（按需） | 状态/上下文/决策/后果 |

详细模板见 `.trae/skills/vibe-flow/SKILL.md` 末尾。

## 与本包其他部分的关系

- `3_Prompt/` —— 用户提示词的优化规范。AI 拿到用户输入后先过这层，优化标准就是符合本文件的要求
- `4_Expand/` —— 用户自定义拓展。AI 主动吸收，冲突时主动提醒用户
- `1_Configuration/` —— 系统内部配置，与本文件无直接关系，用户不用管
